# Cineworld API Wrapper

Unofficial browser-assisted Python wrapper mapped from Cineworld UK browser traffic.

## Why login uses your real browser

Cineworld currently protects login with Cloudflare Turnstile. A failed capture showed the Playwright-launched browser submitting:

- `captcha: false`
- no valid Cloudflare clearance state
- `POST /api/login` -> HTTP `403`
- `cf-mitigated: challenge`

A known-good browser login instead submitted a real Turnstile token and reached Cineworld's JSON login API.

Because of that, v0.2.0 does **not** try to manufacture, bypass, or fake Cloudflare values. It launches your installed Chrome/Edge as a normal visible process using a dedicated local profile, attaches only so it can observe Cineworld's responses, fills the supplied details if requested, and leaves the actual **Log in / Turnstile interaction to you**.

Once Cineworld accepts the login, the wrapper captures the generated Cineworld session values and reuses the authenticated browser session.

## First login

```python
from getpass import getpass
from cineworld import Cineworld

email = input("Cineworld email: ").strip()
password = getpass("Cineworld password: ")

with Cineworld(browser_mode="native") as cw:
    session = cw.login(
        email,
        password,
        auto_submit=False,
    )

    print("Logged in:", session.authenticated)
    print(cw.get_orders())
```

What happens:

1. Installed Chrome/Edge opens with `.cineworld/profile-native`.
2. Cineworld's real login page loads.
3. The wrapper fills your email/password.
4. **You click Log in yourself.**
5. Complete any visible Cloudflare/Turnstile step normally.
6. The wrapper observes the successful `/api/login` response.
7. `SessionToken`, member/session metadata and browser cookies are generated by Cineworld/Cloudflare and retained locally.

Your email/password are not written to the wrapper's session file.

You can also enter everything yourself:

```python
with Cineworld(browser_mode="native") as cw:
    session = cw.login(timeout=300)
```

or run:

```powershell
python examples\manual_login.py
```

## If Cloudflare still blocks the login

The wrapper now reports this separately from a bad password. If you see a message saying Cloudflare challenged the request before Cineworld authentication, do not keep retrying automatically. Close the wrapper, reopen it, and complete the login/challenge manually in the native browser window.

For a completely fresh browser state you can remove only the wrapper profile:

```powershell
rmdir /s /q .cineworld\profile-native
```

Do **not** delete your normal Chrome profile; the wrapper uses its own dedicated folder.

## Booking-session flow

The wrapper exposes the calls observed in the capture up to the final confirmation/payment page. It does not implement a completed payment because no completed payment was present in the capture.

```python
with Cineworld() as cw:
    cw.login(email, password, auto_submit=False)

    vista = cw.create_vista_session()
    print("Booking session:", vista.get("UserSessionId"))
```

`CreateVistaSession` uses the Cineworld `SessionToken` produced by login plus the literal `WebBookingLogin`; it does not resend your account password.

`add_tickets()` and `set_seats()` affect live booking inventory. Do not loop them or use them to hold inventory unnecessarily.

## Notes

- Cineworld can return HTTP 200 with an application-level login error, so the wrapper checks the JSON `errorCode`, `statusCode`, and `userMessage` too.
- A Cloudflare HTTP 403 challenge is now reported separately from an invalid Cineworld password.
- Normal `/api/login` can return `UserSessionId: null`; the booking-side ID is established later by `CreateVistaSession`.
- Cineworld JSON POST/PUT requests use `Content-Type: application/json` in the capture.
- No credentials, cookies, CAPTCHA tokens or session tokens from the HAR are embedded in this project.
